# Closed-bar causal replay usage

## Scope

`ClosedBarCausalReplay` is a bounded, offline replay spine for supplied,
immutable evidence. It runs the supported `level_reversal:5m` internal-reversal
path and advances only supplied tracker state through the accepted closed
lifecycle. By default selected plans remain observations only. The separately
documented opt-in outer-admission binding may register one advisory tracker row
when its exact causal evidence is supplied; see
`docs/architecture/OUTER-ADMISSION-CAUSAL-REPLAY-USAGE.md`.

It is not a general historical replay runner. In particular, public reports
continue to expose `ready_for_replay=False` and `ready_for_training=False`.
Those flags are deliberate: this component supplies a raw, resumable ledger,
not a public readiness decision.

## Construct a supplied-evidence run

All inputs are caller-supplied. Choose one explicit, timezone-aware initial
time which exactly matches the initial `CausalWatchStorage` and
`CausalAdmissionContext` decision times. Construct one `ReplayClock` at that
time and pass that same object to both providers and the replay runner.
`ReplayEvidenceBundle` has no `start_at` field; the initial clock time comes
from the supplied provider evidence.

```python
from trading_system.tree_replay import ClosedBarCausalReplay, InternalReversalInputs
from trading_system.tree_replay.admission_context import CausalAdmissionContext
from trading_system.tree_replay.causal_replay_checkpoint import ReplayProviderBaseline
from trading_system.tree_replay.causal_replay_contracts import ReplayEvidenceBundle
from trading_system.tree_replay.clock import ReplayClock
from trading_system.tree_replay.watch_storage import CausalWatchStorage

initial_time = supplied_initial_time
clock = ReplayClock(initial_time)
watch = CausalWatchStorage(
    seed=supplied_watch_seed,
    decision_time=initial_time,
    clock=clock,
)
admission = CausalAdmissionContext(
    instrument="OANDA:XAUUSD",
    decision_time=initial_time,
    tracker_seed=supplied_tracker_seed,
    quote_seed=supplied_quote_seed,
    log_seed=supplied_log_seed,
    busy_seed=supplied_busy_seed,
    newline="LF",
    frame_requests=supplied_frame_requests,
    publications=supplied_publications,
    lock_steps=supplied_lock_steps,
    clock=clock,
)
baseline = ReplayProviderBaseline.capture(watch=watch, admission=admission)

bundle = ReplayEvidenceBundle(
    run_id="caller-supplied-run-id",
    instrument="OANDA:XAUUSD",
    events=supplied_events,
    anchors=supplied_anchors,
)
inputs = {
    "pass-0": InternalReversalInputs(
        snapshot_id="caller-supplied-snapshot-id",
        map_requests=supplied_map_requests,
        reversal_requests=supplied_reversal_requests,
    ),
}
replay = ClosedBarCausalReplay(
    bundle,
    clock=clock,
    watch=watch,
    admission=admission,
    reversal_inputs=inputs,
    # Omit this mapping to retain default OBSERVE_ONLY behavior.
    outer_admission_inputs=supplied_outer_admission_inputs,
    baseline=baseline,
)
ledger = replay.run()
```

`events` and `anchors` must be immutable tuples. Events are strictly ordered by
`(available_at, sequence)`; anchors are strictly ordered by `decision_time`.
The current bundle accepts only exact `OANDA:XAUUSD`. The runner supports only
the `level_reversal:5m` source variant. An unsupported pass remains explicit in
the ledger; it is never replaced by a different producer or inferred input.

Each pass ID must have an exact `InternalReversalInputs` instance in `inputs`.
Missing or invalid input records a blocked diagnostic; it does not use a
fallback. A selected internal-reversal plan remains `OBSERVE_ONLY` when
outer-admission inputs are omitted. When explicitly opted in, the retained
private plan is evaluated through the bounded outer-admission source path and
can yield `ADMITTED_TRACKER`, `REJECTED`, or `BLOCKED`; none is an economic
outcome. See the outer-admission usage document for its evidence contract.

## Bind events to the providers they drive

Every `ReplayEvent` payload declares its own `available_at` timestamp, equal to
the event's `available_at`. A payload may carry an `evidence_binding`, and when
it does, its exact JSON shape is:

```json
{
  "consumer": "INTERNAL_REVERSAL_INPUT",
  "artifact_id": "pass-0",
  "artifact_digest": "lowercase-sha256-of-the-canonical-supplied-artifact"
}
```

The consumers are `INTERNAL_REVERSAL_INPUT`, `ADMISSION_PUBLICATION`, and, for
an opted-in outer-admission pass, `OUTER_ADMISSION_INPUT`. `artifact_digest` is
the lowercase SHA-256 generated by `canonical_evidence_digest(...)`; bindings
are not inferred from a matching ID, time, or similar payload.

For every supported anchor, `required_event_ids` must contain exactly one ID.
That required event must itself be available by the anchor decision time and
must be the unique `INTERNAL_REVERSAL_INPUT` binding for the anchor's pass ID
and the canonical digest of its exact `InternalReversalInputs` object.

For every admission publication due at an anchor,
`admission.replay_publications_through(anchor.decision_time)` requires exactly
one eligible `ADMISSION_PUBLICATION` binding. Its artifact ID is the exact
publication ID; its digest is the canonical digest of that publication; and
its event kind, channel identity, and availability must agree with the supplied
publication. The runner performs these checks before advancing admission,
loading/saving watch state, running lifecycle resolution, or evaluating the
producer. Missing, duplicate, future, substituted, or mismatched bindings
block the pass.

## Run prefixes, resume, and inspect the ledger

Run a legal prefix with `run_until(pass_count)`. It returns the current
`ReplayRunLedger` and a detached canonical checkpoint dictionary. Keep the
captured `ReplayProviderBaseline` separately; the checkpoint records its
fingerprint, not substitute provider objects.

```python
prefix_ledger, checkpoint = replay.run_until(1)

resumed = ClosedBarCausalReplay.restore(
    checkpoint,
    bundle=bundle,
    clock=ReplayClock(resume_time),
    baseline=baseline,
    reversal_inputs=inputs,
    outer_admission_inputs=supplied_outer_admission_inputs,
)
ledger = resumed.run()

for record in ledger.records:
    print(record.pass_id, record.outcome, record.digest)
    for commitment in record.consumed_event_commitments:
        print(commitment.event_id, commitment.available_at, commitment.payload_digest)
```

For restore, `resume_time` must equal the checkpoint clock time and must bind
to the newly constructed clock. Restore rejects a changed bundle fingerprint,
baseline fingerprint, ledger hash, event/anchor order, checkpoint checksum, or
provider snapshot mismatch. A legal uninterrupted run and a legal
checkpoint/resume split are expected to yield the same ordered ledger digest.

`ReplayRunLedger.records` contains immutable `ReplayPassRecord` objects.
`record.as_dict()` and `ledger.as_dict()` are suitable for inspection of the
structured ledger. Every record contains the consumed event IDs, a hash-chain
predecessor digest, activation state, detached candidate data when selected,
lifecycle messages, diagnostics, and the provider-baseline fingerprint.
The evidence diagnostic exposes `ReplayEventCommitment` values: event ID,
availability, sequence, full canonical payload digest, and any declared
consumer/artifact binding. The ledger retains those commitments rather than raw
event payloads, so it is raw-payload-free by default.

## Audit the retained source order

The runtime does not import or execute retained source. Independently verify
the pinned, parsed outer-pass projection with the required source root:

```powershell
python -B tools/check_causal_replay_source_parity.py --source-root C:\Users\roeea\AppData\Local\Temp\tr-tree-source-review-4efd65cf2e284d97a81199af6195f149
```

The command emits JSON only. `VERIFIED` establishes the static source-order
projection and still leaves both readiness flags false. A `BLOCKED` report is
not permission to approximate source order or continue with a substituted
source variant. Its legacy `unwired_outer_admission` projection means the
static auditor does not execute an outer-admission runtime. It does not negate
the separately documented, opt-in evidence-bound adapter.

## Excluded scope and permissions

This bounded offline spine does not provide any of the following:

- Historical vendor-data acquisition, raw-market-data retention, inferred feed
  availability, revisions, calendar synthesis, venue conversion, or symbol
  aliases; hidden threshold choices; or open-only/partial-base observations.
- Full source-owned outer admission beyond the limited documented
  `level_reversal:5m` path, multi-producer arbitration, or a claim of complete
  source execution. The opt-in bounded admission path remains advisory only.
- Other producer paths or a synthetic fallback; broker/order handling, fills,
  delivery, live action, filesystem discovery, network access, or retained
  source execution.
- A counterfactual policy that records every eligible plan, or tracker
  registration outside the exact opt-in evidence-bound outer-admission path.
- Economic simulation, costs, spreads, slippage, time-exit policy, portfolio
  exposure, outcome labels, dataset construction, feature allowlisting,
  training, calibration, model evaluation, shadow operation, or deployment.

The component therefore does not grant production-data approval, raw-data
retention approval, model-promotion approval, live-trading approval, broker
execution approval, capital-allocation approval, or deployment approval.
